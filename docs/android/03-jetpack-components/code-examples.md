## 1. Proper StateFlow Collection (The "safe" way)
**Bad**: Collecting directly in `lifecycleScope`.
```kotlin
// In Fragment
lifecycleScope.launch {
    viewModel.state.collect { /* Update UI */ } // Danger! Continues in background.
}
```

**Good**: `repeatOnLifecycle`.
```kotlin
viewLifecycleOwner.lifecycleScope.launch {
    viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.state.collect { /* Update UI */ }
    }
}
```
*Why?* This behaves like LiveData. It stops collecting when the view is stopped, preventing crashes and saving battery.

## 2. WorkManager Chaining
Running tasks A -> B -> C only if WiFi is on.

```kotlin
val constraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.UNMETERED)
    .build()

val workA = OneTimeWorkRequestBuilder<UploadWorker>()
    .setConstraints(constraints)
    .build()

val workB = OneTimeWorkRequestBuilder<ProcessWorker>().build()

WorkManager.getInstance(context)
    .beginWith(workA)
    .then(workB)
    .enqueue()
```

## 3. Navigation with SafeArgs
**Bad**: Using Bundles manually.
```kotlin
val bundle = Bundle()
bundle.putString("id", "123")
navController.navigate(R.id.detailFragment, bundle)
```

**Good**: Type-safe arguments generated by the plugin.
```kotlin
val action = HomeFragmentDirections.actionHomeToDetail(userId = "123")
navController.navigate(action)
```
*Receive side:*
```kotlin
private val args: DetailFragmentArgs by navArgs()
val userId = args.userId
```
